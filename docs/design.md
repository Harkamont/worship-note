# 찬양노트 첫 버전 설계

2026-10-18 대화에서 사용자가 승인한 범위: PNG/JPG 단선율 악보 업로드, AI 인식 및 교정, 멜로디·조표·코드 전조, 코드 추가·수정, 구간 이름, 송폼, PNG와 송폼 기반 가사 TXT 다운로드. 인식 API와 모델을 교체 가능하게 구성한다.

## 동작

- 왼쪽은 원본/작업 정보, 가운데는 편집 가능한 악보, 오른쪽은 구간·송폼·가사 편집. 작은 화면에서는 패널을 탭으로 전환한다.
- 악보의 원본은 이미지이며, 음표·박자·코드·가사·구간·송폼은 별도 JSON으로 저장한다. 전조한 구조로 악보를 다시 그려 PNG로 출력한다.
- 샘플은 직접 작성한 짧은 연습곡으로 명시한다. 업로드한 이미지는 인식 성공 전 샘플 데이터로 대체하지 않는다. 새 업로드와 저장된 악보를 혼동하지 않는다.
- AI는 서버에서만 호출한다. 키는 브라우저·소스·로그에 넣지 않는다. 키 설정이 없으면 503과 명확한 안내를 반환하고 원본은 유지한다.
- OpenAI Responses와 OpenAI 호환 Chat Completions 어댑터를 분리한다. 기본 모델은 공식 API 확인 후 선택하고 서버 환경값으로 변경한다. 모델별 결과 비교를 위해 사용 토큰·걸린 시간·모델을 기록한다.
- 가사 TXT는 송폼의 각 구간과 반복 횟수를 실제 순서로 펼친다. 구간명 포함과 가사 없는 구간 포함을 선택할 수 있다. 누락된 구간 참조와 빈 가사를 알린다.
- PNG 내보내기는 실제 악보 SVG를 흰 배경의 고해상도 이미지로 변환한다. MusicXML과 프로젝트 JSON도 내보내고 다시 불러올 수 있다.
- 작업은 현재 브라우저에만 보관하며 외부 공개 악보 목록이나 공유 기능은 넣지 않는다.

## 성공 기준

1. 샘플에서 C→D 전조 시 음표와 C/E→D/F#이 함께 바뀐다.
2. V1→C→V2→C×2 송폼의 가사 TXT는 반복을 포함한 순서를 보존한다.
3. PNG/JPG 업로드, 편집과 저장 복원, 실제 PNG 다운로드를 브라우저에서 확인한다.
4. 잘못된 이미지와 잘못된 AI JSON을 거부하고, 키 부재를 성공으로 표시하지 않는다.
5. 타입 검사·도메인 테스트·서버 경로 검증·배포 빌드와 독립 리뷰를 완료한다. 실제 AI 호출은 승인된 키가 연결된 뒤에만 검증한다.

## 현재 인증 상태

사용자는 Score_project 키 생성 대상으로 조직과 프로젝트를 선택했다. 처음 로컬 저장 확인은 미승인 상태로 반환되었으며, 사용자가 이후 앱의 .env.local 저장을 명시적으로 허용했다. 새 키를 해당 위치에 저장하고 비공개 Sites 서버에도 secret으로 설정했다. 실제 API 호출과 모델 지원 여부는 별도 검증한다.
