# 초기 개발·측정 기록

이 문서는 초기 개발 과정과 당시 측정 결과를 보관한 기록입니다. **현재 설치·사용 방법은 [README](../README.md)와 [사용 안내](USER_GUIDE.md)를 확인하세요.** 아래의 과거 앱 이름, 설정 방법, 기능 한계, 저장 방식, 비공개 작업 폴더 링크는 현재 시험판과 다를 수 있습니다. 당시 기록과 수치는 변경하지 않고 유지합니다.

PNG/JPG 단선율 찬양 악보를 읽고, 키·코드·가사·구간·송폼을 편집하는 비공개 웹앱입니다.

## 사용

1. PNG/JPG 악보를 올리고 인식을 시작합니다. 원본 이미지는 인식이 성공할 때까지 기존 작업을 덮어쓰지 않습니다.
2. 원본과 비교하며 음표, 점음표, 붙임줄, 코드와 가사를 고칩니다. 코드 박 위치는 **4분음표를 1박으로 계산하며 1부터 시작**합니다. 6/8의 1·2·3박은 각각 1·3·5번째 8분음표입니다.
3. 키를 바꾸면 멜로디, 조표와 분수코드의 베이스가 함께 전조됩니다.
4. 구간을 만들거나 복제하고 송폼의 순서·반복 횟수를 정합니다.
5. 고해상도 악보 PNG, 송폼에 맞춰 반복을 펼친 가사 TXT, MusicXML, 원본 포함 프로젝트 JSON을 받습니다.

작업은 현재 브라우저의 IndexedDB에 저장됩니다. 브라우저 데이터를 지우거나 다른 기기를 쓰기 전에 프로젝트 JSON을 보관하세요. 예제 「오늘의 찬양」은 이 앱을 위해 직접 만든 연습곡입니다.

## 전용 음표 인식과 코드·가사 보완

이미지 업로드의 기본 선택은 **이 기기에서 음표 읽기 · 4부 악보 포함**입니다. 로컬 인식기가 준비돼 있으면 API 키 없이 원문 MusicXML을 만들고 검토할 수 있습니다. 코드·가사 AI를 쓰려면 인식 방법을 별도로 선택합니다. **전용 음표 인식 + 코드·가사 AI**는 HOMR가 읽은 고정된 마디의 가사·코드만 AI에 요청합니다. 서버는 음높이·음가·점·붙임줄·구간·송폼을 변경하지 않고 주석만 병합합니다. AI 응답의 형식·음악 검증에 실패하면 기존 작업을 보존합니다.

`AI_ANNOTATION_MODEL`과 `AI_ANNOTATION_OUTPUT_FORMAT`으로 보완 모델과 출력 형식을 전체 인식 모델에서 따로 선택할 수 있습니다. 보완 모델을 생략하면 `AI_MODEL`을 사용합니다. 보고된 `usage.cost`가 있으면 인식 정보와 프로젝트 JSON에 저장하며, 비용이 없는 응답을 0달러로 표시하지 않습니다.

현재 검증한 보완 프로필은 OpenRouter의 `openai/gpt-6-sol`, `AI_ANNOTATION_OUTPUT_FORMAT=json_schema`, `AI_ANNOTATION_SERVICE_TIER=flex`입니다. Flex는 OpenRouter의 OpenAI 모델 보완에만 적용하고 `openai/flex` 제공처로 한정해 다른 가격 경로로 자동 변경하지 않습니다. 다른 모델·제공처를 선택할 때는 이 선택값을 비우거나 `default`로 바꿉니다. 전체 인식 요청은 별도 기존 설정을 유지합니다.

MusicXML 파일은 **악보 파일 불러오기**에서 원문을 보존해 미리 보고 XML·TXT로 다운로드합니다. 단순 편집기에 가져오기는 별도 선택입니다. MXL과 단순 편집기는 단일 파트·보표·성부를 지원하며, 음가 합 불일치·다성부·잇단음표 등은 마디별 오류를 보고합니다. 음표나 쉼표를 자동으로 채워 맞추지 않습니다. 가져오는 동안 편집과 새 작업을 잠시 막아 이전 파일의 늦은 완료가 새 작업을 덮어쓰지 않도록 합니다.

### 로컬 실행

현재 시험한 HOMR는 공식 저장소 커밋 `ab369ac54277afab582afa4725441f7cbba76593`입니다. 별도 Python 환경과 모델은 앱 저장소 밖 `../work/homr-runtime`, `../work/homr-source`에 준비했습니다. 실행 파일·모델·API 키는 사이트 소스에 포함하지 않습니다. [HOMR 공식 설치와 라이선스](https://github.com/liebharc/homr)를 참고하세요.

로컬 `.env.local`에 `OMR_BASE_URL=http://127.0.0.1:3101`과 충분히 긴 임의의 `OMR_AUTH_TOKEN`을 설정하고, 앱 폴더에서 `node scripts/omr-companion.mjs`를 별도 실행합니다. Python·소스·작업 경로는 `.env.example`의 선택 변수로 바꿉니다. Python 가상환경 실행 경로는 `venv/bin/python`을 그대로 지정합니다. 심볼릭 링크의 실제 대상으로 바꾸면 가상환경의 패키지를 찾지 못할 수 있습니다.

Companion은 로컬 주소·토큰 인증·CORS 미허용·한 번에 한 작업·고정된 실행 파일과 인자·작업 폴더 정리를 적용합니다. 입력 10MiB, MusicXML 2MiB, 처리 60초 상한입니다. Worker는 같은 사이트 요청만 받아 설정된 서비스에 중계합니다. **게시된 Worker에는 Python을 설치하지 않았으며 로컬 주소를 게시 사이트에 연결하지 않습니다.** 원격 앱의 전용 인식을 쓰려면 별도 인증된 OMR 실행 서버가 필요합니다. 원격 설정이 없는 사이트에서는 MusicXML 가져오기와 코드·가사 보완을 사용할 수 있습니다.

### 실제 이미지 비교

사용자가 제공한 600×927 PNG 한 장(24마디·114개 음표/쉼표)을 확대 판독해 기준을 만들고 원본 입력으로 비교했습니다. 수동 정답은 인식 엔진이나 AI 프롬프트에 제공하지 않았습니다.

| 방법 | 음높이+음가 일치 | 붙임줄 | 비고 |
|---|---:|---:|---|
| Qwen3.8 전체 이미지 | 69/114 | 별도 기록 | 완성 악보 검증 실패 |
| Audiveris 2배 확대 | 88/114 | 5/14 | 리듬·동시음 오인 |
| HOMR 공식 위 커밋 | 112/114 | 14/14 | 24마디 모두 4박 |

HOMR는 음높이·쉼표 종류 114개를 모두 맞췄으나 14마디의 점8분+16분을 8분+8분으로 읽었습니다. 제목 오인과 원본에 없는 장식 기호 4개도 별도 오류입니다. 98.2%는 음높이·음가 일치율이며 전체 악보 정확도가 아닙니다. 모델 다운로드를 마친 뒤 반복 처리 4.258초, 같은 XML 해시를 확인했습니다. 로컬 장비·전기·향후 서버 비용은 API 0달러와 별개입니다.

HOMR + Sol standard 보완 1회에서는 가사 114/114, 코드 기호 순서 48/48, 같은 마디의 코드 47/48, 확정된 마디+박+기호 41/47이 맞았습니다. 이 보완 호출은 $0.024066·8.729초였으며, 코드 박 오류와 원래 음가 오류는 수동 검토가 필요합니다. 무료 Nemotron과 저가 Qwen·Luna 보완은 잘못된 마디·가사 개수 등으로 검증을 통과하지 못했습니다. 단일 PNG의 결과를 다른 악보로 일반화하지 않습니다.

Flex의 초기 호출은 두 코드를 하나로 합쳐 검증에 실패했습니다. 단일 코드 문법과 인접 라벨 분리 지침을 추가한 뒤 한 번의 Flex 호출에서 가사 114/114, 코드 기호+마디 48/48, 확정된 마디+박+기호 43/47을 확인했습니다($0.012253·11.191초). 이는 같은 표본의 실패를 보고 조정한 결과입니다. 원본의 14마디 음가 두 개, 2·6·10마디 F#m/E와 20마디 E의 박은 교정이 필요했습니다. 16마디 E의 박은 원본에서 확정하지 못해 정확도 분모에서 제외했습니다.

최종 로컬 UI의 이미지 한 번 업로드 시험은 HOMR→Sol Flex 병합까지 16.257초에 성공했습니다. 자동 결과는 음높이+음가 112/114, 가사 값 114/114(한글 84음절·연장 표시 20개·빈 쉼표 10개), 코드 기호+마디 48/48, 확정 코드 박 45/47, 붙임줄 14/14입니다. 이 호출은 입력 5,131토큰 중 5,128토큰이 캐시돼 $0.0063858이었으므로 새 악보의 예상 비용으로 쓰지 않습니다. UI에서 14마디 음가 두 개와 12·20마디 코드 박 두 개를 고친 뒤 A→G→A 전조, 3마디/줄 PNG와 프로젝트 JSON·가사 TXT 다운로드를 확인했습니다. 가사 TXT는 현재 음표에 붙은 음절을 마디별로 연결하므로 자연스러운 띄어쓰기·문장별 줄바꿈은 별도 편집이 필요합니다. 원본에 없는 템포 80과 구간 ‘전체’·송폼 1회는 기본값이며, 16마디 E의 박과 생략된 슬러·장식기호는 검토 대상으로 남깁니다.

## AI 설정과 교체

키는 서버에서만 사용합니다. 승인된 `.env.local`은 Git에 포함하지 않습니다. 변수 이름과 기본값은 `.env.example`에 있습니다.

- 기본: `AI_PROVIDER=openai`, `AI_MODEL=gpt-6-luna`, OpenAI Responses.
- 교체: `AI_PROVIDER=openai-compatible`, `AI_BASE_URL`과 `AI_MODEL`, `AI_API_KEY`를 설정합니다. 이미지 입력을 지원하는 Chat Completions 호환 서비스가 필요합니다. 다른 제공자에게 OpenAI 키를 보내지 않도록 호환 제공자는 `AI_API_KEY`만 사용합니다.
- 출력 형식: 호환 제공자는 기본 `AI_OUTPUT_FORMAT=json_object`를 사용합니다. 지원하는 제공자는 `json_schema`로 엄격한 출력을 요청할 수 있습니다. `prompt`는 출력 형식 옵션을 보내지 않고 프롬프트로 JSON을 요청합니다. 세 모드 모두 앱에서 음악 데이터를 다시 검사합니다.
- 모델별 사용 토큰과 걸린 시간, 제공자가 보고한 비용은 인식 결과에 보관됩니다. 비용이 제공되지 않으면 별도 요금표로 확인합니다.
- 로컬 환경 파일과 배포된 사이트의 환경 변수는 별도입니다. 배포 환경은 Sites secret 설정으로 관리합니다.

실제 확인(2026-10-18): OpenAI 직접 API는 크레딧 부족, Z.ai 무료 GLM은 과부하 또는 잘못된 출력으로 인식을 마치지 못했습니다. 이후 사용자 OpenRouter 키 인증과 실제 유료 요청을 확인했습니다. Qwen3.7 Flash의 추론을 끈 설정으로 직접 만든 16마디 PNG를 UI에서 읽고 편집 악보로 변환했습니다. 원본 64개 음표 중 음높이 62개, 음가·가사 64개, 코드기호 16개 마디가 일치했으며 처리시간은 61.7초였습니다. 이 단순 예제의 결과를 일반 악보 정확도로 해석하면 안 됩니다.

사용자가 제공한 실제 24마디 악보에서는 Qwen3.7·Qwen3.8·Luna·Nemotron 무료 모델의 전체 이미지 출력이 모두 악보 검증을 통과하지 못했습니다. GPT-6 Sol도 전체 이미지에서는 리듬 오류가 남았습니다. 첫 줄을 분리해 3배 확대한 이미지 + Sol + strict schema 조합에서는 수동 대조한 15개 음표/쉼표의 음높이·음가·점·붙임줄과 한글 10음절이 일치했으나 코드 박 위치 오류가 있었습니다. 다른 줄에는 음표 추가·붙임줄 누락 등이 남았으므로 전체 자동 인식의 정확도나 제품 준비가 확인된 상태는 아닙니다. 앱의 데이터 형식 검증과 실제 원본 일치 여부를 구분해야 합니다.

### 저렴한 비전 모델 시험 설정

Z.ai 무료 모델을 먼저 시험할 때의 설정입니다. 별도 Z.ai Standard API 키가 필요합니다. 공식 문서가 비전 모델의 `response_format` 지원을 확정하지 않으므로 `prompt`로 시작합니다.

```dotenv
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://api.z.ai/api/paas/v4
AI_MODEL=glm-4.6v-flash
AI_OUTPUT_FORMAT=prompt
AI_API_KEY=
```

OpenRouter에서 Qwen을 비교할 때의 설정입니다. 별도 OpenRouter 키가 필요합니다.

```dotenv
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://openrouter.ai/api/v1
AI_MODEL=qwen/qwen3.7-flash
AI_OUTPUT_FORMAT=json_object
AI_REASONING_ENABLED=false
AI_API_KEY=
```

OpenRouter는 필요한 요청 옵션을 지원하는 제공처 중 가격이 낮은 순으로 연결합니다. `AI_REASONING_ENABLED=false`는 추론 기능을 끄는 설정입니다. 값을 생략하면 제공자의 기본 설정을 사용합니다. OpenAI Responses와 Z.ai 요청에는 이 옵션을 보내지 않습니다.

2026-10-18 공식 표기 기준 GLM-4.6V-Flash는 무료이며, OpenRouter Qwen3.7 Flash는 100만 토큰당 입력 $0.03·출력 $0.13부터입니다. GLM-4.6V-FlashX는 입력 $0.04·출력 $0.40이며 아직 실제 호출하지 않았습니다. 실제 24마디 전체 이미지 요청의 OpenRouter 청구 비용은 Qwen3.7 $0.00123395, Qwen3.8 $0.00335907, Luna $0.002651425, Nemotron 무료 $0이었으나 모두 사용 가능한 완성 악보를 내지 못했습니다. 요금만으로 모델을 선택하지 말고 같은 악보의 오류와 교정 시간을 비교하세요. 전조·송폼·PNG/TXT 출력에는 AI를 다시 호출하지 않습니다.

근거: [Z.ai 가격](https://docs.z.ai/guides/overview/pricing), [Z.ai 이미지 입력](https://docs.z.ai/guides/vlm/glm-4.6v), [Z.ai 출력 형식](https://docs.z.ai/api-reference/llm/chat-completion), [OpenRouter Qwen3.7 Flash](https://openrouter.ai/qwen/qwen3.7-flash).

## 지원 범위

단선율, 온/2분/4분/8분/16분음표, 점 한 개, 쉼표, 붙임줄, 장·단조 전조, 코드 기호, 구간과 송폼을 지원합니다. 피아노 양손 반주보·다성부·셋잇단음표·못갖춘마디 등은 이번 데이터 형식으로 충실히 표현하지 못할 수 있습니다. AI에 없는 음표·코드를 추측해 채우도록 하지 않으며, 음악 데이터 검증을 통과하지 못한 결과는 거부합니다.

PNG는 최대 32MP/한 변 16384px 안에서 출력합니다. 복잡하거나 긴 가사는 한 줄의 마디 수를 줄여 확인하세요. 원본의 글꼴·배치와 동일한 복원은 보장하지 않습니다.

## 7종 악보로 추가한 XML 검토와 가사·코드 보완

이미지 인식 방법에서 **HOMR 음표 XML 유지 + 코드·가사 AI**를 선택하면 로컬 음표 XML을 먼저 보존하고 AI는 가사·코드만 추가합니다. 잇단음표·여러 성부·못갖춘마디·조표 변경을 단순 편집기에 맞추어 버리지 않습니다. 코드·가사 단계가 실패하거나 취소되어도 HOMR 초안을 확인하고 다운로드할 수 있으며 자동 유료 재시도는 하지 않습니다. 여러 보표에서는 첫 보표의 주요 성부를 선택하고, 같은 시작 위치에서는 최고음 하나에만 새 가사를 붙입니다. 그 밖의 성부에 이미 있는 가사는 보존합니다.

새 보완 설정은 기존 단순 편집기 보완과 분리합니다. `AI_XML_ANNOTATION_MODEL=openai/gpt-6.1-sol`, `AI_XML_ANNOTATION_OUTPUT_FORMAT=json_schema`, `AI_XML_ANNOTATION_SERVICE_TIER=flex`, `AI_XML_ANNOTATION_REASONING_EFFORT=low`입니다. Flex는 다른 가격의 제공처로 자동 전환하지 않습니다. 환경 파일과 키는 버전 관리에 포함하지 않습니다.

**MusicXML로 정밀 변환**은 이미지를 AI가 직접 전체 XML로 쓰는 별도 시험 기능입니다. `AI_MUSICXML_MODEL`, `AI_MUSICXML_SERVICE_TIER`, `AI_MUSICXML_REASONING_EFFORT`로 설정합니다. 이 방식이 항상 더 정확하지 않습니다. 7종 개발 표본에서는 완성 XML이 6종에서 나왔고, 같은 음표 표본에서 로컬 전용 엔진보다 크게 틀린 악보도 있었습니다. high 추론의 초기 시간초과와 중단·불완전 응답도 비용에 포함해야 합니다. 전체 악보 정답률로 일반화하지 않습니다.

가사 프로젝트 데이터와 MusicXML은 절 번호·syllabic·extend·end-line을 보존합니다. 가사 TXT는 독립된 늘임 표기만 제거하며, 실제 단어의 하이픈은 유지합니다. XML에 없는 정확한 띄어쓰기나 송폼은 자동으로 추측하지 않습니다. XML의 인쇄 순서 가사와 기존 편집기의 송폼에 따른 가사는 구분합니다.

XML 검토는 구조·박자 검사이며 원본 인식 정확도의 보증이 아닙니다. XML에 문제가 있거나 단순 편집기가 지원하지 않아도 원문 파일은 다운로드할 수 있습니다. 미리보기는 OSMD 2.2.1이 생략하는 복잡 코드·괄호를 정확히 표시하기 위해 렌더링용 복사본만 문자 표기로 바꿉니다. 원문 XML의 음표나 코드 정보는 바꾸지 않습니다. 검토 결과는 자동 저장되지 않으므로 XML·TXT·검토 JSON을 내려받으세요. 검토 JSON을 다시 여는 기능은 아직 없습니다.

7종 실측 원문·단가·문자 오류율·코드 순서 F1·독립 음표 표본 및 실패 비용은 작업 폴더 바깥 `../outputs/MusicXML_직접변환_개선및평가.html`에 있습니다. 기존 측정 기록과 이번 측정은 다른 설정과 표본을 섞어 평균 내지 않습니다.

`호환 XML`은 MusicXML 요소 순서만 정리한 다운로드 복사본입니다. HOMR의 key·voice·alter 순서 오류를 정리하며, 음표·코드·가사·박자 해석이 같음을 비교한 뒤 내보냅니다. 원문 XML 다운로드는 그대로 유지합니다. 표본의 XSD 통과는 악보 인식 정확도나 모든 외부 편집기의 동작을 보증하지 않습니다.

## 찬송가 4부 악보에서 멜로디만 남기기

MusicXML 검토창의 **찬송가를 멜로디 악보로**에서 남길 파트·보표·성부를 고른 뒤 **멜로디 악보 만들기**를 누릅니다. 선택한 성부의 화음에서는 최고음 하나를 남기고, 그 화음에 붙어 있는 여러 절 가사와 기존 코드 기호를 유지합니다. 원래 4부 XML은 별도로 유지하며, 단선 초안의 XML·가사 TXT 다운로드와 편집기로 가져오기를 제공합니다. 단선화에는 AI 요청이나 추가 API 비용이 없습니다. 로컬 HOMR의 음표 전용 결과에는 코드·가사가 없으므로 별도 입력이나 선택한 AI 보완이 필요합니다.

추천 성부는 확정된 소프라노가 아닙니다. 인식 엔진이 마디마다 성부 번호를 바꾼 경우에는 경고를 확인하고 원본과 비교해야 합니다. 다른 성부의 움직이는 음을 자동으로 합치지 않으며, 선택하지 않은 성부에만 가사 절이 있거나 다른 파트에 코드가 있어 손실될 경우에는 추출을 중단합니다. 잇단음표·못갖춘마디 등은 XML에 유지하지만 현재 단순 편집기로 가져오기는 지원 범위에 따라 제한됩니다. 단선 결과는 검토창을 닫기 전에 XML로 보관하세요.

제공된 「천사 찬송하기를」 시험에서는 297개 음표·쉼표가 78개로 줄고, 기존 코드 35개와 3절 가사가 유지됐습니다. 21마디를 편집기로 가져올 수 있고 출력 XML의 MusicXML 4 스키마 검사를 통과했습니다. 독립적으로 읽은 첫 5마디의 음높이·음가·시작 박 동시 일치는 추출 전후 모두 14/19로, 원래 음표·성부 인식 오류를 고친 결과는 아닙니다. 전체 찬송가의 인식률로 해석하지 않습니다.

## 0.2.0-beta.3 · 못갖춘마디와 여러 성부 편집

짧은 첫 마디를 실제 길이로 가져오며, 자동 추정한 경우 확인 안내를 남깁니다. 중간의 짧은 마디는 XML의 명시적인 표시를 따릅니다. 마디별 길이는 프로젝트·전조·구간 나누기·재출력에서 보존합니다.

여러 성부의 같은 오선에서 멜로디를 자동 선택하는 옵션을 추가했습니다. 동시에 시작하는 음 중 높은 음을 선택하며 붙임줄·긴 음·쉼표를 보존합니다. 원래 성부를 직접 고르는 옵션도 유지합니다. 자동 선택은 소프라노 정답이나 원래 인식 오류 수정을 보장하지 않습니다.

일반 검사를 통과하지 못한 단선 결과는 ‘검토용으로 열고 고치기’를 직접 선택할 수 있습니다. 지원하는 음표의 길이를 보존하고, 틀린 박자와 마디 밖 코드 위치를 표시합니다. 음표가 잠시 없는 수정 중 상태도 저장합니다. 명시된 빈 시간은 같은 길이의 쉼표로 바꾸며, 중간 조표는 첫 조표로 표시하고 개별 음높이를 보존합니다. 잇단음표·32분음표 등 지원하지 않는 표기는 계속 거절합니다. 초안 XML에는 검토 안내와 목표 마디 길이를 보관해 다시 열 때 오류가 못갖춘마디로 바뀌지 않게 했습니다.

XML·MusicXML·MXL 모두 원본 비교와 멜로디 선택을 거쳐 가져옵니다. AI로 현재 악보에 가사·코드를 붙일 때도 기존 원본 비교 작업을 보관합니다. 화면은 ‘무료로 음표 읽기’, ‘AI로 가사·코드 추가 (유료)’, ‘AI로 악보 전체 읽기 (유료)’로 비용과 효과를 안내합니다. 비용을 받지 못한 유료 결과는 무료로 표시하지 않습니다.

개발 표본 PNG에서는 33마디·129개 멜로디 음표/쉼표와 1박 첫 마디를 일반 편집기로 가져왔습니다. JPG 4부 찬송가는 19마디·39개 선택 음표/쉼표에 원본 빈 시간 두 곳을 쉼표로 표현하고, 6마디를 수정 대상으로 유지했습니다. 이 수치는 출력 내용과 편집 가능 여부이며, 정답 인식률이 아닙니다. 외부 악보 이미지는 공개 소스 묶음에 넣지 않습니다.
